# Model整理の確認記録

確認日: 2026-10-06（日本時間）

## 変更内容

- `PhotoRecord` は写真ドキュメントID・Storageファイル名・日時・楽曲・Live Photo動画名を保持します。`LibraryPhoto` はそのメタデータと読み込んだ画像を一体で保持します。
- `PhotoFolder` はフォルダID・タイトル・日時・手紙を保持します。写真・フォルダの画面は配列の添字ではなくIDで選択・コピー・削除します。
- `UserProfile` は名前・メールの解釈とログイン時の保存形式を共通化します。`SharedFolderReference` は既存NFC文字列の変換をまとめます。
- `FirebaseMusic` に保存形式の変換をまとめ、写真IDとSpotify曲IDを区別します。
- 写真・フォルダのFirebaseアクセスを `PhotoLibraryRepository` に移しました。ViewModelは画面の状態と読込の世代を管理し、ViewはModelを表示します。シート表示や編集ツールの選択など、UIだけの状態はView/ViewModelに残しています。
- 画像取得が途中で失敗しても、残りの写真のID・日付・楽曲がずれません。写真一覧の順次表示は維持し、古い読込結果や削除前の結果が画面へ戻ることを防ぎます。
- NFC取り込みでは写真の全フィールドをコピーし、コピー元IDでコピー先を読み直す重複処理を削除しました。失敗時にも処理中フラグを解除します。

## 互換性

Firestoreのパスと既存キー `url/date/livephotoUrl/artistName/trackName/id/imageName/previewUrl` を維持しています。`id` フィールドは曲IDで、写真IDはFirestoreドキュメントIDです。フォルダコピー・NFC取り込みでは生のドキュメントをコピーし、未知のフィールドも残します。

`all` の特別扱い、NFCの `ユーザーID フォルダID` 形式、WidgetのApp Group `group.PIcTune` と `first/second/third` キーも維持しています。フォルダ表紙は従来と同じく最新1件だけを取得します。
