# PicTune 共通デザイン基準

## 状態と対象

この文書は PicTune の画面に共通して使うデザインの基準です。現時点では設計案であり、アプリの画面・アセット・認証方式にはまだ適用していません。既存のラベンダーの背景、チェキ、音楽、手紙、アプリアイコンの柔らかい色を出発点にしています。

目指す印象は「大切な思い出を、音楽と一緒にしまっておく小さなアルバム」です。写真と文章を読みやすく保ち、紙・チェキ・音符・リボンの装飾は入口や空状態などに絞ります。写真一覧、検索、設定では操作と内容を優先します。

## 色

色は用途で呼びます。同じ紫でも、背景用と文字・操作用を混同しません。背景の 2 色は既存の `ColorModel` の値を 16 進数に丸めたものです。

| 用途 | ライト | ダーク | 使用箇所 |
| --- | --- | --- | --- |
| 背景 | `#F7F2FF` | `#201A2B` | 画面の基本背景 |
| 背景グラデーション開始 | `#C7D4FA` | `#302446` | ログイン、写真・フォルダ一覧の背景 |
| 背景グラデーション終了 | `#E3BFFA` | `#3F2B55` | 同上。文字を直接重ねる場合は背景色とのコントラストを確認する |
| カード・入力欄 | `#FFFDFB` | `#30273D` | 情報カード、フォーム、手紙の台紙 |
| 主な文字 | `#25213B` | `#F8F3FF` | 見出し、本文 |
| 補助の文字 | `#5B526B` | `#D4C9E2` | 日付、説明、補足 |
| 主な操作 | `#59459F` | `#BCA8F2` | 主要ボタン、選択状態、リンク |
| 主な操作の上の文字 | `#FFFFFF` | `#201A2B` | 主要ボタンのラベル |
| 境界線 | `#DED2EE` | `#56496A` | 入力欄、カードの薄い輪郭 |
| ローズ | `#B95E7A` | `#E8A5BA` | ハート、シールなどの装飾。本文には使わない |
| クリーム | `#FFF6E8` | `#4A3C42` | 手紙やチェキの小さな背景 |

- 主要ボタンは深い紫に白文字を使います。淡いラベンダーは広い背景に使い、白文字のボタンには使いません。
- エラー・破壊的操作・成功は iOS の意味色を基本とします。ローズをエラーの代わりに使いません。
- Apple・Google の認証ボタンはサービス名が明確に読める独立した表示にし、PicTune の主要ボタンとは区別します。
- 上記のライト配色では、基本背景に対する主な文字は約 14.1:1、補助の文字は約 6.7:1、カード上の主な操作色は約 7.5:1 です。グラデーション・画像上の文字は実画面で別途確認します。

## 文字

日本語の UI は iOS のシステムフォントと Dynamic Type の役割を使います。外部フォントは追加しません。英語の `PicTune` ロゴのみセリフ体を使い、本文と見分けられるようにします。装飾的な日本語見出しは、端末で可読性を確認できるまでシステムフォントを使います。

| 役割 | SwiftUI の基準 | 使い方 |
| --- | --- | --- |
| 画面タイトル | `.largeTitle`、太字 | 写真、フォルダなどの画面名 |
| 感情的なコピー | `.title`、太字 | ログイン入口、空状態の短い言葉。原則 2 行以内 |
| セクション見出し | `.headline` | フォルダ名、曲名、フォーム見出し |
| 本文・ボタン | `.body` | 説明、入力、主な操作 |
| 補足 | `.subheadline` | アーティスト名、日付、補足 |
| 小さな注記 | `.footnote` | 利用条件や補助説明。重要な操作説明には使わない |

- 固定ポイント数の指定を避け、文字サイズの変更で折り返し・縦方向の拡大に対応します。
- 日本語の本文を中央揃えにしないことを基本とします。ログイン入口の短いコピーのみ中央揃えにできます。
- `Roboto` のような指定だけが一部画面に残らないよう、画面実装時は上記の役割に置き換えます。

## 形・余白・奥行き

| 要素 | 基準 |
| --- | --- |
| 余白の段階 | `4 / 8 / 12 / 16 / 24 / 32 pt` |
| 画面左右の余白 | `20 pt` を基本とし、内容が多い一覧は `16 pt` |
| 主要ボタン・入力欄 | 高さ `52 pt`、角丸 `14 pt`。最小タップ領域 `44 pt` |
| カード | 角丸 `18 pt`、内側余白 `16 pt`、薄い境界線または控えめな影 |
| 小さなチップ | 角丸 `12 pt`、横余白 `12 pt` |
| チェキ | 白い余白と下部の広い余白を持つ。写真そのものを装飾で覆わない |

影は紙・チェキ・前面にある操作だけに使い、一覧のすべての要素に重ねません。浮いている部品は 1 画面に 1～2 種類までにします。グラデーションは画面背景か主な操作のどちらかに絞り、カードの中まで重ねません。

## 共通部品

- **主なボタン**：紫の塗り、明確な動詞、処理中は進行表示、二重実行防止。
- **補助ボタン**：カード色の背景と薄い輪郭。破壊的操作はシステムの赤を使います。
- **入力欄**：カード色、薄い輪郭、外側に常時見えるラベル。エラーは入力欄の下に文章で表示します。
- **情報カード**：チェキ、曲、フォルダ、手紙で同じ内側余白と角丸を使います。画像比率や個別の情報配置は内容に合わせます。
- **空状態**：小さなイラストまたは SF Symbol、短い説明、必要なときだけ 1 つの操作を置きます。
- **ナビゲーション**：iOS 標準の戻る操作、シート、タブを基本とします。独自の装飾は内容領域に置きます。

## 画面への当てはめ

- **ログイン**：チェキ・レコード・手紙を重ねた絵を主役にし、Apple・Google・メールを最初の画面で選べる構成にします。メールのログイン・新規登録・再設定は同じ入力部品を使います。
- **写真一覧・フォルダ一覧**：淡い背景、写真や表紙が主役のカードにします。装飾は空状態と見出し付近に絞ります。
- **写真詳細・音楽**：チェキと曲名を読みやすくし、再生・停止の状態を文字とアイコンで表します。
- **手紙**：クリーム色の紙を使えますが、長文入力では文字の可読性を優先します。
- **設定・削除確認**：iOS 標準のフォームと確認ダイアログを基本とし、装飾で意味や危険度を曖昧にしません。

## 確認する条件

実装時はライト・ダーク表示、大きな文字、画面幅の狭い端末、キーボード表示、読み上げ、読み込み中・失敗・空状態を確認します。背景と文字の組み合わせ、タップ領域、写真の見え方を実際のシミュレーターまたは実機で確認してから適用済みと記録します。
