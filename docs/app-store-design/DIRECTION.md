# PicTune App Store画像の現状調査・デザイン検討

調査日: 2026-11-06 / 対象コミット: `e1d9508` / 段階: 構図検討

## 依頼と対象

ユーザーの参考画像にある、鮮やかな背景、大きな文字、白縁の立体的な装飾、端末との重なりをPicTuneの紹介画像へ展開するための調査です。対象はApp Storeの紹介画像であり、アプリUIの改修ではありません。対象者は「友人との写真を、曲やメッセージと一緒に残して贈りたい人」と仮定しています。新機能・マスコット・アプリアイコンの変更は含みません。

## 現状

コードとリポジトリ内の確認記録・画像を照合しました。今回アプリを新規ビルド・起動したものではありません。公開中のApp Store掲載内容やApp Store Connect内の登録素材は未確認です。

| 項目 | 確認できた内容 | 画像制作への影響 |
|---|---|---|
| 既存の見た目 | 写真一覧のラベンダー背景、チェキの白枠、詳細のシステム背景、共有画面の封筒 | 白いチェキと封筒は、濃い広告背景にも合わせやすいです |
| アイコン | チェキ・ヘッドホン・プレゼント箱 | 広告の装飾も同じモチーフで統一できます |

| 落書き | 保存済みチェキの再編集、ペン、スタンプ | 指で書いた短い言葉を見せると、機能と感情が同時に伝わります |
| 手紙＋招待 | `FolderInvitationView.swift`、`WriteLetterView.swift`。リンクで送り、封筒を開いて受け取る画面 | 「思い出をプレゼント」のコピーを実画面で裏付けられます |

| 撮影素材 | 検証用画像の多くが図形やサンプル曲名。古いUIの画像も混在 | 本番の紹介画像は、同じ最新版ビルド・同じ端末で再撮影が必要です |

## 参考画像から取り入れるもの

1. 一瞬で読める、2行程度の短い大見出し。
2. 強い色面と白い面の対比。全ページを淡い色だけでまとめない構成。
3. 厚みのある文字、白縁、短い影によるステッカーの質感。
4. 主役の実画面を大きく置き、意味のある小物を前後に重ねる構図。
5. 一枚につき一つの価値を見せる、連続したポスターとしての統一感。

参考画像の猫・コイン・宝箱は複製しません。PicTuneのアイコンにもあるヘッドホン、チェキ、手紙、プレゼントに置き換えます。「派手」は色数の多さより、文字の大小差と奥行きで作ります。

## 3方向の比較

[比較用HTML](explore.html) / [比較画像](preview/sheet.png)

比較のため、3方向とも同じ開封済みの実画面とコピーを使用しています。画面内部のテスト図形を実写真に見せかけて差し替えてはいません。端末の縁とDynamic Islandは広告用HTMLの装飾です。

| 方向 | コンセプト | 得意な点 | 今回の判断 |
|---|---|---|---|
| A: ポップなギフト | PicTuneは、思い出を包んだおもちゃのパッケージ | 濃いピンク、丸い文字、白縁のヘッドホン、厚みのある見出し | 参考の楽しさと派手さに最も近く、中心方向として扱います |
| B: 音楽のジャケット | PicTuneは、思い出の曲を収めたレコードジャケット | 黒とミント、大きな文字、レコードの溝 | 音楽は伝わりますが、今回の参考より落ち着き、音楽プレーヤーにも見えやすいため主方向にはしません |
| C: 手紙のラッピング | PicTuneは、写真を包んだ贈り物 | 明るい地色、明朝体、オレンジのリボン | 手紙の温かさはありますが、今回求められた派手さが弱いため主方向にはしません |

色のピンクは確定したブランド変更ではありません。既存アイコンのプレゼント箱の色を強めた、広告上の比較案です。参考の青と同じ色を採ることより、立体感・太い文字・画面との重なりを優先しました。競合の最新ランキングや広告効果の調査は行っていません。上記は視覚表現の比較判断であり、転換率を実証したものではありません。

## A方向の制作基準

- 背景は濃いピンク、主役の台紙は白、立体文字・ヘッドホンは黒に近い紫。淡いラベンダーは実画面と既存アイコンの中に残します。
- 基準キャンバスは440×956、3倍で1320×2868 px。見出しは約56 px相当、補足は17 px相当。左右余白は28〜32 px相当です。
- 見出しは丸ゴシック。現在の比較はmacOSのヒラギノ丸ゴを使っています。参考の風船のような文字に比べると線の太さは控えめなので、最終制作時の文字造形は残作業です。
- 実画面の写真・フォルダ名・曲名が読み取れる大きさを保ちます。装飾は操作や主要コンテンツを隠さない位置に置きます。
- シリーズではピンク地と白地を交互に使い、文字位置と端末の扱いは統一します。5枚すべてを同じ傾きの端末だけで並べない構成にします。
- 既存の開封演出がPicTune固有の見せ場です。静止画では、封筒からチェキと手紙が出た状態を採用します。新しいアニメーションの実装は必要ありません。

## 5枚の掲載構成

| 順番 | 見出し案 | 必要な実画面・内容 |
|---|---|---|
| 1 | 思い出を、プレゼント。 | チェキと手紙の開封画面。写真・音楽・手紙を贈る全体像を伝えます |
| 2 | あの日の写真に、あの曲を。 | 写真詳細。写真と曲名を同時に見せ、利用できる場合に限り試聴操作も掲載します |
| 3 | 落書きまで、思い出に。 | 写真編集。短い手書き文字と少数のスタンプが載った状態 |
| 4 | 伝えたいことは、手紙で。 | フォルダに添えた手紙。短く具体的なメッセージが読める状態 |
| 5 | 大切な日を、ひとつに。 | 写真入りフォルダ一覧。旅行・誕生日などをまとめた状態 |

設定・ログイン・権限ダイアログは主要5枚に含めません。QR/NFCは実機での一連の確認が残るため主訴求に使いません。ウィジェットも今回の実装状態の追加検証は行っていないため、掲載構成には含めません。

## 本制作に必要な素材

- 掲載許諾を確認した、旅行・友人・誕生日などの写真を3〜5枚。人物写真は写っている方の許諾も確認します。
- 公開用の架空の名前・フォルダ名・手紙。実際のアカウント情報は使いません。
- 掲載できる楽曲情報・アートワーク。アプリ内で検索できることと広告への掲載条件は分けて確認します。
- 最新ビルドで写真詳細・落書き・手紙・フォルダ・開封を再撮影した画面。
- 保存済みチェキ編集のFirestoreルール反映状況の確認。既存確認記録では本番反映を作業範囲に含めていません。

## App Storeの仕様

2026-11-06にApple公式情報を確認しました。

- 6.9インチ向けの縦画像には1320×2868 px等が受け入れられます。今回はこの寸法を基準にしています。[スクリーンショット仕様](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)
- 文字・装飾を重ねる構成は可能ですが、実際の利用画面とアプリの価値を示す必要があります。紹介画像をタイトルやイラストだけにはしません。[ガイドライン2.3.3の解説](https://developer.apple.com/help/app-review/guideline-reference/2-3-3-screenshots)
