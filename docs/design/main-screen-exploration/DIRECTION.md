# PicTune メイン画面・3方向の比較

> 更新：ユーザーの「もっとポップで可愛いのが良い」を受けた最新版は [POP-DIRECTION.md](POP-DIRECTION.md) です。以下は初稿の判断記録として保持しています。

## Brief

- 依頼：既存PicTuneのメイン画面を3案検討。ユーザー指定は「方向を絞らず比較する」。
- 目的：写真とその日の音楽を振り返り、友人と残すiOSアプリ。開いてすぐ写真を見返す／撮影に進めることを優先します。
- 成果物：同じ写真ライブラリを使った3枚の完成イメージ、比較HTML、現状との比較、評価記録。SwiftUIへの反映・アイコン変更・追加画面の制作は今回の範囲外です。
- 雰囲気・参照物はデザイナー補完です。A＝写真アルバム、B＝レコードジャケット、C＝子どもの頃のたからばこ。
- 素材：既存のチェキ枠と画面記録を確認。実写の収録がないため、出典を確認したUnsplashの写真をサンプルとして使用します。生成画像・有料クレジットは使用していません。
- アカウント・実データは使用しません。写真27枚、日付、楽曲の対応は比較用の架空データです。

## Current app

参照：`sotsugyo/View/main/NewSignInedView.swift`、`MainImageView.swift`、`MainContentView.swift`、`ColorModel.swift`。
画像：`docs/screenshots/photo-folder-toolbar/photos.png`（既存の確認記録。今回の再撮影ではありません）。

現状は大きな「写真」見出し、2列のチェキ一覧、右上のカメラ、写真・フォルダ・設定の3タブです。
手動監査：青紫〜薄紫のグラデーションが写真より先に目に入ります。曲の情報は一覧から判別できず、余白と写真サイズが均等で視線の起点が弱い状態です。
旧画面は画像を使ったbefore.htmlで保存します。ラスタ画像内の文字・階層はDOMスキャンでは検出できないため、旧画面の自動判定を改善の証拠には使いません。

### Keep / lose / unknown

- [x] 写真ライブラリの写真を主役にする。
- [x] チェキ／装飾済み画像の全体を開いて確認できること。サムネイルの切り抜きは表示だけで、元画像は変更しません。
- [x] 写真タップ→詳細、日付と紐づく曲名・アーティストの対応。
- [x] 撮影→任意のQR交換という既存の流れ（導線を仕様に保持）。
- [x] 写真・フォルダ・設定の3タブ。フォルダ内の手紙、NFC、招待、写真の共有・保存は既存画面に残します。
- [x] 長押しによるフォルダ追加／削除、下への引きで再読込は実装時にも保持する前提。
- Lose：一覧背景の紫グラデーション、一覧で写真と音楽の関係が見えない状態。
- Unknown：実ユーザーの写真の縦横比、白枠／スタンプの密度、写真枚数。今回は同一サンプルで比較します。

### 決めていないこと

本依頼は3方向の比較です。採用案を確定せず、すべてを同じ段階で提示します。名称・タブ構造・既存機能の削除はありません。Cの見出し「写真のたからばこ。」は画面の表現案で、アプリ名の変更ではありません。

## Three directions

| 案 | コンセプト | source family | ground | type | accent hue | richness |
|---|---|---|---|---|---|---|
| A · 日々のアルバム | PicTuneは、写真の余白に曲を添えるアルバムです。 | object | light | serif | green | photo |
| B · 音のギャラリー | PicTuneは、思い出の写真をジャケットにしたレコード棚です。 | media | dark | expanded | yellow | shape |
| C · 思い出のたからばこ | PicTuneは、写真を一枚ずつ取り出すたからばこです。 | play | colour-field | rounded | blue | colour-material |

3案とも背景・書体・豊かさの源・アクセントの色系統を変えます。現在のlookは `object / colour-field / grotesque / violet / colour-material` として扱い、各案は5列中3列以上異なります。作業開始時にグローバル履歴ファイルは存在しませんでした。
作業完了時に、採用案を決めず3方向すべてをグローバル履歴に記録しました。

### 比較の観点

- A：写真の一覧性、チェキとの自然なつながりが強み。音楽の印象と造形の意外性はB/Cより控えめです。
- B：写真と音楽の結びつきが最もはっきり見えます。一度に比較できる写真の枚数はAより少なくなります。
- C：既存のスタンプや手紙との相性と、触れたくなる印象が強み。一覧を素早く探す効率はAに劣ります。
- デザイン上の検証軸はBです。PicTuneの「写真＋音楽」を、一枚のジャケットとして同時に表せるためです。A/Cを不採用とはせず、今回の成果物は3案の並列比較で止めます。

### 避ける定型

写真一覧の単純な等間隔グリッドだけで終えること、音楽アプリ風の再生履歴ダッシュボード、日記アプリ風の挨拶＋ベージュ背景には寄せません。業界順位・現行製品の優劣を調査したものではなく、構造上の定型としての整理です。現状の薄紫グラデーション、中央の＋、指標カード、色違いの機能タイルも使いません。

## Art direction

Aは自然光と控えめな彩度の写真を大きく見せ、キャプションを白い余白に置きます。Bは写真をレコードスリーブに見立て、背後の円と溝を一種類の線幅で描きます。写真は全面に出し、レコード造形が主役を奪わない比率にします。Cは青い箱の段差、白いチェキの厚み、少しずれた写真の重なりで、触れるものとして描きます。新規の装飾機能を足したことを意味しません。

## Signature storyboard（構想／HTMLのみ）

共通のトリガーは写真タップです。HTMLで写真が大きくなり、その写真に紐づく曲名と日付が現れます。

1. 0ms：押した写真の形を保ち、0.98倍の押下フィードバック。
2. 80〜300ms：写真を拡大し、背景の一覧を沈めます。Bではジャケットを棚から取り出す、Cでは箱から引き上げる意味を持ちます。
3. 420ms：拡大写真の下に日付・曲が揃います。閉じると元の一覧に戻ります。
4. 実装時のhaptic：写真が止まった時のみlight impact。HTML／静止画では触覚を再現しません。
5. Reduced Motion：移動・拡縮を止め、120msの表示切替。情報は同じです。

これは既存の写真詳細への遷移を磨く構想です。自動再生・ホーム上での試聴は追加しません。カメラ、Firebase、QR、NFC、タブ先の機能はHTMLには接続していません。
